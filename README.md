# GitCheck · Git 仓库接入体检

GitCheck 面向需要接手公开 GitHub 仓库的开发者。体检报告按分支和 commit 标记版本，帮助定位接入资料缺失、Windows 脚本、硬编码路径和疑似敏感信息，并展示就绪度评分和主要风险。

## 当前进度

- 前端可用 Mock 演示仓库输入、分支选择、扫描状态、评分和风险筛选。
- 后端已实现公开性校验、分支分页及供后续扫描复用的 commit SHA 解析。后端接口详见 [backend/README.md](backend/README.md)。
- 真实文件读取、扫描和评分仍待实现，前端当前使用 Mock 数据。

## 本地运行

使用 Node.js 22.18 或更高版本和 npm。在两个终端中分别运行以下命令。

后端

```sh
cd backend
npm ci
npm run dev
```

默认监听 3000，`GET /api/health` 可检查服务状态。可通过环境变量 `PORT` 调整端口，调整后需同步修改 Vite 代理目标。服务端可通过 `GITHUB_TOKEN` 提供 GitHub 访问凭据。

前端

```sh
cd front
npm ci
npm run dev
```

打开 Vite 输出的地址，在「体验示例」中选择公开仓库。扫描 `main` 可查看示例风险，扫描 `release/clean` 可查看无风险样例。通过「加载更多」选择 `audit/partial` 可体验部分覆盖。更多示例见 [front/README.md](front/README.md)。

前端和后端均可在各自目录运行 `npm run build`。后端编译后用 `npm start` 启动。

## 更新跟踪设计

1. **发现更新。** 以仓库和分支为单位保存最近一次成功报告对应的 commit SHA。重新检查时读取该分支当前 SHA，相同则复用报告。
2. **避免全量重算。** 对比旧 SHA 和目标 SHA，重扫新增和修改文件，移除已删除文件的发现，再重算仓库级检查和评分。差异不完整、规则变化或读取预算影响文件选择时，回退到受限的全量扫描。
3. **标记报告版本。** 一次扫描固定使用目标 SHA。报告同时展示仓库、分支、commit、扫描时间和覆盖范围。
4. **失败与限流。** 保留最后一份成功报告及其版本，显示本次更新失败或限流。限流时按服务端返回的重试时间重新尝试。初次扫描失败时展示错误。

更新跟踪当前为设计，完整需求与验收标准见 [SPEC.md](SPEC.md)。
