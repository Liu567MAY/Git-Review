请以我提供的 GitCheck.html 为唯一前端视觉和交互参考，开发名为 GitCheck 的 Git 仓库接入体检工具。先完成可运行的前端，后续接入真实扫描 API。不要重新设计页面，不要增加无关功能。

1. 技术栈：Vue 3 + Vite + TypeScript，原生 CSS，Canvas 负责背景动画。组件按业务模块拆分，避免把全部逻辑堆在 App.vue。无需引入重型 UI 库。
2. 完整保留 HTML 的页面布局：顶部导航、仓库输入、扫描流水线、接入就绪度及风险分布、四类检测结果总览、风险审查、AI 接入建议、报告记录。
3. 视觉采用 GitHub Light 风格：背景 #f6f8fa、面板 #ffffff、正文 #1f2328、次级文字 #656d76、边框 #d0d7de、主操作绿 #1f883d、链接蓝 #0969da、高危红 #cf222e、中危黄 #9a6700、低危灰 #8c959f。参考 GitHub Primer 的系统字体栈（-apple-system, BlinkMacSystemFont, Segoe UI, Noto Sans, Helvetica, Arial, sans-serif），正文 14px / 1.5，常规字重 400、标题和按钮 600；代码、路径及 Commit SHA 使用 ui-monospace, SFMono-Regular, SF Mono, Menlo, Consolas, Liberation Mono, monospace。保持原型的工程化排版、6px 圆角、细边框和克制留白，导航激活态使用 GitHub 风格的珊瑚色下划线，风险分类选中态使用浅蓝底；不要强制加载外部字体，不使用大面积渐变、重阴影或装饰性卡片。
4. 背景保留两侧黑白灰像素块、左侧 Git Commit 分支树、右侧文件目录与扫描矩阵。鼠标接近时像素轻微亮绿，Git 节点低频流动；扫描期间加快信号并显示矩阵扫描线。动效不遮挡正文，支持移动端和 prefers-reduced-motion，组件卸载时释放动画资源。
5. 报告以功能为主：保留简洁总分、明确接入结论、优先处理事项和可点击风险分布，禁止恢复大面积四维评分进度条。四个检测模块支持展开具体检测项，并联动筛选风险清单。
6. 风险清单支持分类标签、严重程度下拉筛选、排序下拉、问题/文件/规则编号搜索、重置；每行可展开，展示规则 ID、脱敏代码证据、风险原因与修复建议。AI 建议支持展开/收起。
7. 前端数据和 API 请求集中管理，定义 TypeScript 类型。初期使用明确标记的 Mock 数据，不得把演示结果当成真实检测；后续由真实扫描状态驱动进度（可以使用 SSE），覆盖未扫描、扫描中、成功、失败、空结果及部分扫描状态。报告标注仓库、分支、commit SHA、检测覆盖范围。AI 模块失败时不影响静态报告。
